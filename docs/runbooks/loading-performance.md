# 移动端加载与图片复用（2026-11-21）

目标是缩短打开聊天及图片显示的等待。保持现有匿名身份、后端归属校验、私照授权、发送幂等键和未完成回合恢复；不更换服务、不新增原生依赖、不迁移数据库。

Auth manager 仅在验证并保存身份后向 ready snapshot 暴露 owner；退出、身份丢失、恢复失败时不暴露 owner。不相信旧全局 viewer 查询的用户 ID，不静默创建替代游客。viewer 缓存按 owner 分区，60 秒新鲜期；响应 ID 必须匹配恢复身份。后台读取同一身份时不撤销 userId，不卸载聊天和草稿；首次或无数据仍需要用户记录成功建立后才能访问钱包/聊天。

角色公开目录在已恢复的匿名会话下与 /me 并行获取；每个 HTTP 仍用 SDK token 并通过服务端 Auth guard。角色、列表、详情、时间线新鲜期 30 秒，挂载与聚焦共用 query key，通过 fetchQuery 复用新鲜结果及进行中请求。Discover 目录加载后预取聊天列表；点击聊天并行预取详情与首屏时间线。背景/姓名可由同 owner 的后端聊天列表作过期种子，详情继续向后端校验。Match 已创建会话也可使用已验证角色作种子。

后台临时网络错误保留已有数据，列表和聊天提供刷新重试；首次失败显示错误。401、403、404、契约错误或身份变化不能用旧缓存继续展示；403 归入 unauthorized。钱包缓存最多 10 秒，扣钻后的取消旧请求和重新读取保留。查询只缓存进程内，不新增本机历史副本；冷启动仍需恢复身份和请求服务器。

公开角色的封面、头像、聊天背景与相册背景使用原生 force-cache；URL 沿用现有服务端有效窗口。替换封面产生新路径/URL，不命中旧图缓存。Discover 预载当前及下一位封面，Chats 预载前三个头像，点击会话及 Match 时预载选中封面。队列最多 2 个并发、8 个排队、单次最多 3 个来源；成功记录最多 128 个、5 分钟 JS 去重，失败可重试。实际文件由原生 Image/系统缓存管理，不承诺永久离线。队列禁止加入私照 access URL；私照继续校验 owner/conversation/photo、短链和打开状态，未授权不预取，不改价格/权限/扣钻。

本轮继续使用上传时已处理的封面文件，没有独立生成头像缩略图/封面中图，没有批量改写旧文件；首次下载体积和网络往返仍存在，不能称为持久化缩略图库或 CDN 地域优化。

QueryClient/QueryObserver 覆盖首次并发去重、再次挂载无重复 viewer 请求、刷新中 owner 不变、不同 owner 隔离、临时失败保留、无权限拒绝旧缓存，以及详情/时间线并行预取复用。Auth 测试验证 owner 只在 ready 后暴露且 SIGNED_OUT 后撤销。图片测试覆盖去重、替换 URL、TTL、失败重试、并发上限及非 HTTPS/带账号 URL 拒绝。

真实开发 Supabase 探针使用一次性匿名身份，经实际 Auth manager、移动传输和 schema 读取 /me、角色、空列表；实际 QueryClient 模拟下一页挂载时新增请求 0。身份及业务记录清理，无模型、支付或运营内容修改。云端数据不是 iPhone/弱网耗时。

发布前 pnpm check、fingerprint；官方 EAS 导出发布后验证已安装 runtime 获取新 manifest。真机需确认首次/再次 Discover、Chats→会话、替换封面、发消息/草稿、弱网重试及私照/扣钻。旧 group 6ff8a23b-7a67-4654-871c-ced2ebd48584 保留为回退选项。后续服务端耗时、独立缩略图及首次下载压缩需要另行实现测量，不以本轮客户端发布替代这些工作。

## 2026-11-23：重启后的最近文字记录

新增本机历史快照，替代上文“仅进程内缓存”限制；图片、余额和授权仍不持久化到此快照。当前身份恢复成功后，先恢复同 owner 的 viewer、最近最多 30 个列表条目及最多 5 个会话的最近完成文字（每会话最多 40 条，实际还受容量上限限制），再后台向服务器同步。只缓存已完成的 user/assistant 文字；照片、授权、钱包、临时链接和 pending 回合排除，pendingStore 的发送键恢复规则保留。完整历史和图片仍按需联网读取。

快照使用已安装 expo-crypto 的 AES-256-GCM 加密，随机 nonce、owner/环境作为 AAD；密文写入 AsyncStorage，独立密钥存入 WHEN_UNLOCKED_THIS_DEVICE_ONLY 的 SecureStore。没有明文降级，Web 不持久化。明文序列化上限 160 KB、7 日读取有效期；过期/损坏/密钥丢失时弃用并按网络路径恢复，不更换游客身份。缓存失败不阻断 App。数据超过容量时减少旧记录，保留消息原文，不截断消息内容；列表预览最多 200 字。

缓存恢复有 1 秒等待上限，慢读可稍后补齐但不能覆盖较新的服务器数据，身份改变时不再注入。恢复数据标为过期，后台校验照常进行；缓存不作为权限依据。已知身份/资源拒绝、删除及响应异常会清除快照，拒绝的会话不会因后续 viewer 刷新而复活。最近成功回复会立即并入进程内时间线，缓存写入及切后台尽力完成；强杀瞬间尚未完成的写入不能保证落盘，服务器仍为最终记录来源。

为了避免首次恢复时的短暂整页转圈，有缓存时先显示历史，草稿读取完成前只禁用输入；无缓存仍显示首次加载。首次安装此更新后需先打开常用聊天并成功获取记录，才有下次重启可用的快照。过期会话凭证的恢复、没有缓存的旧记录和网络同步仍有耗时，不承诺所有冷启动为零等待。

## 2026-11-23：已打开的聊天私照

采用 SDK 58 官方 expo-image 58.0.18（iOS SDWebImage / Android Glide），只替换 PhotoCard 的图片组件。`memory-disk` 复用原生缓存，source.cacheKey 使用当前 owner、photo ID 和私有 Storage 对象路径；去掉签名 token，保留其他查询参数。短链续签不再改变图片身份。后台替换照片会产生新对象路径，随后访问切换到新缓存，不复用旧版文件。

已有 opened 偏好保留并兼容旧值，仅在图片成功显示后记录无 token 的 cacheKey。重开时先通过 expo-image 的 readFromCacheAsync 读取原生缓存，命中后立即提供 ImageRef，同时后台续签/检查版本。没有自建图片下载、文件目录、LRU 或新的数据库。iOS 图片缓存上限 256 MiB、解码内存成本上限 64 MiB，淘汰由原生库处理；系统仍可能回收缓存，不能承诺永久离线或精确零毫秒。

本机索引不是授权；仅当前身份下、服务器照片元数据已授权且 available、已打开的照片允许使用缓存。401/403、资源不存在、响应异常立即阻止显示；临时 unavailable 保留已有授权照片。新版本识别前可能短暂显示上次版本，后台返回新路径后切换。重启后照片元数据仍从服务器取得，不写入文字快照；本轮解决的是重复下载和等待签名，不是首次身份/历史同步的所有延迟。无缓存或已淘汰时仍需下载，失败保留现有短链重试。授权与扣钻 API 不改。

新增原生依赖必须生成并覆盖安装新的 Preview 包，fingerprint 必须与原 b4df9f57f70164fd26cbb42fa72cbd05834321ca 不同；禁止向旧 runtime 强推新模块 JS。不要卸载旧 App，以保留匿名身份和现有本机记录。旧版本已下载的 RN Image 文件不迁移；新版首次显示成功后建立 expo-image 缓存。
