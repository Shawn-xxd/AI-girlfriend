# V1 轻量摘要记忆

实现范围见 ADR 0013。只有后台改动，沿用现有聊天界面、匿名身份、供应商适配器和内容审核；没有新增依赖或平台。

## 行为

- 每个会话一份摘要，会话按用户/角色唯一。近期完整成功回合默认保留 10 轮，并受 24000 字符预算约束；摘要最多 2000 字符。
- 默认每新增 10 轮更新一次。长消息先达到字符预算时，用预算内的完整回合提前更新。只使用 completed 的完整文字消息对，不使用照片、拒绝或失败内容。
- 成功聊天后机会式触发，回复不等待摘要。当前进程最多同时运行两个任务；数据库 180 秒租约防止多实例重复生成，旧租约不能覆盖新内容。失败保留旧摘要并冷却 60 秒，由后续聊天重试；没有常驻队列或无人聊天时后台补算承诺。
- 摘要作为带引号的用户数据传给模型，不加入角色系统指令；当前明确陈述优先。摘要基于用户明确表达的事实，助手猜测不作为用户事实。生成结果经输出审核后才保存。
- 删除文字消息会清空摘要并使在途任务失效；删除会话/用户级联清理其记忆和用量。有效聊天次数、等级和照片权限仍按现有独立记录保持。

## 配置与成本

无需新增凭证，默认复用当前生成供应商、模型及审核器。可选服务端配置：

```dotenv
MEMORY_ENABLED=true
MEMORY_BATCH_TURNS=10
```

关闭后忽略已存摘要并停止生成，近期上下文继续工作。一次更新有一次生成与一次输出审核，不自动重试付费调用。已有成功且经过审核的消息作为源，不重复做整批输入审核。用量保存在 companion_memory_usage，generation/output_moderation 各一条、按 generation_id 幂等；平台成本统计应与 companion_ai_usage_events 一起汇总。记录可得的 Token 数，不猜测未知用量或单价。

## 迁移与测试

在开发 Supabase 应用 `supabase/migrations/20261110000100_chat_memory.sql`，保留既有四份已应用文件不变。业务 SDK 不执行 DDL；当前没有 Supabase 管理 MCP 时需 SQL Editor 执行一次。

```bash
pnpm check
pnpm test:schema
pnpm test:integration
# 手动真实模型验收，最多两次生成与三次审核；不会由普通 CI 自动执行
pnpm test:memory-live
```

隔离 SQL 验证批次、完整消息对、字符预算、隔离、旧租约、失败冷却、用量幂等和删除失效。真实数据库集成使用明确的 AI 替身，验证聊天不等待摘要、旧信息进入后续请求、失败不影响保存、角色/用户隔离和删除后保持等级。

真实模型验收先建立两轮明确测试历史，再实际生成摘要；最近窗口故意缩为一轮，确保原始姓名/兴趣不在窗口内。随后实际提问并校验从摘要回忆信息，核对摘要用量。批次 2、窗口 1 仅在测试进程内生效，测试后还原配置；临时身份、角色和记录清理，不修改运营角色规则。
