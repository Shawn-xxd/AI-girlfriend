# ADR 0014：钻石钱包与永久照片授权

状态：2026-11-11 钱包与 Diamond Photos 已在开发 Supabase 验收；真实 Apple/RevenueCat 订单接入另行交付和验收。

用户已确认：退款追回该订单全部钻石，保留已解锁照片。余额不足记为待追回，后续到账先补足。不新增注册或登录界面。

## 事务边界

- 服务端验证匿名 JWT，actor 只从 guard 取得。钱包初始为 0，不赠送未经确认的额度。
- 钱包、不可修改的交易流水、请求幂等记录、照片永久授权由一个 PostgreSQL RPC 完成。先锁会话，再锁钱包、照片；所有角色共享钱包，串行校验余额，避免并发超支。
- 客户端传 requestKey 和展示时的 expectedPrice；价格变更返回 409，不自动按新价格扣款。重复请求匹配原照片和价格；已拥有照片返回成功且不再扣费。失败不产生流水或授权。
- 钱包净额允许因退款为负；接口分别给出 availableDiamonds=max(0,净额) 和 pendingRecovery=max(0,-净额)。消费不能主动透支。退款流水引用原始正向流水，整单冲回最多一次。
- 后台信用发放/冲回 RPC 仅 service_role 可调用，本阶段没有客户端充值或退款接口，也没有模拟 Apple 订单。后续只有验证过的订单可以调用购买入账，需 PurchaseRecord 和平台交易唯一约束。
- 流水插入触发余额更新，禁止直接改余额及修改流水。用户删除暂受钱包外键限制，Phase 5 实现匿名化与财务保留后才能发布账号删除；没有开放钱包删除 API。测试清理先删除精确测试用户的进度/授权，再删除钱包、用户。

## 照片和界面

- Diamond 照片必须审核通过、发布且配置正整数价格才可新解锁。迁移将旧的未配置价格 Diamond 照片下架，不猜价格。
- Level 老契约保留，新 /gallery 同时返回两类照片。/access 对两类照片都验证归属、永久授权、审核状态及私有存储；短链 60 秒。
- 扣费成功后才显示照片，失联可用原请求键重试；没有客户端扣钻、乐观授权。图片仍在原卡片显示，聊天输入和窗口位置不变。
- Discover、聊天、Gallery 共用按匿名用户隔离的钱包缓存；Preview 不调用真实钱包，余额未知显示 —。购买入口继续明确不可用，直至原生支付配置验收。

## 本轮验收

本机真实 PostgreSQL：余额、退款欠额、追加到账、授权保留、幂等、价格冲突、跨用户隔离、事务回滚、同照片和不同角色并发消费。浏览器验证双击、失败重试、余额更新和原卡片显示。第六份 SQL 已应用并核对校验和，23 项真实开发 Supabase 集成通过（AI 替身，无支付调用），其中新增钱包四项。临时数据清理；证据见 docs/validation/wallet-cloud-2026-11-11.json。

不把本机/浏览器替身通过写成 Supabase 已更新、Apple 已支付或跨设备已恢复。纯匿名用户的跨设备财务归属仍须在接入 RevenueCat 前单独确定；恢复订阅不能直接视为可恢复已消耗的钻石和聊天身份。
