# ADR 0013：V1 轻量聊天摘要

2026-11-10 用户批准基础摘要，要求第一版保持简单。仅后台维护每个会话一份短摘要及近期对话；会话本身按游客/角色唯一，不共享角色记忆，不新增界面、向量库、队列或第三方平台。

默认每积累 10 个已完成且消息完整的回合，后台合并旧摘要和这一批对话。长消息达到输入字符预算时可提前合并完整回合。摘要上限 2000 字符，输入批次和近期上下文均有字符上限。近期明确陈述优先于旧摘要；摘要作为不可信数据传入模型，不改变角色/平台指令、等级或支付状态。

复用当前生成提供商与审核器。一次更新只有一次生成及一次输出审核，记录各自供应商、模型和 Token 用量，不自动重试计费调用。只有已审核的完整成功回合可进入源数据；照片、失败与拒绝不进入记忆。

成功保存聊天后，在进程内机会式触发更新，最多并行两个任务。数据库短租约避免多实例重复处理，完成写入校验租约和版本，失败保留旧摘要并短暂冷却。聊天回复不等待摘要；进程中断后由后续成功聊天重试，没有可靠任务队列或无人聊天时更新承诺。

删除会话/用户会清理摘要和用量。删除文字消息使摘要失效，阻止旧任务恢复已删除内容；等级/照片权限沿用独立记录，不受影响。第一版不提供单独记忆设置页面。

新增迁移先在隔离 PostgreSQL 验证；开发 Supabase 的执行与真实验收独立记录。不能用本机或替身通过代替实际云端通过。
