# ADR 0011：真实匿名闭环验收与部署准备

2026-11-08 用户再次确认全部用户免注册、免登录，不显示已登录/未登录状态，并要求继续开发。当前阶段优先收尾真实游客闭环；不开始未确定计数/价格/退款规则，不把设计预览改成业务实现。

客户端继续在后台创建并保存 Supabase 匿名身份，App 主流程不增加认证入口。验收必须实际使用 publishable key 调用 signInAnonymously，不能用管理员建邮箱账号、magic link 或测试替身代替匿名成功。匿名平台关闭时失败并明确报告，不绕开平台设置。

新增独立手动真实验收：真实匿名身份 → 真实 NestJS 用户/角色/会话 → DeepSeek 审核与流式交付 → 持久化 → 用同一持久化存储重新创建客户端、刷新凭证和重放结果 → 第二匿名身份资源隔离。一个用例最多一次生成及前后两次内容检查，临时身份/角色/业务数据清理；缺前置条件在计费之前失败。平台无关会话/存储核心的重建不冒充 iPhone Keychain 或真机重启验证。

准备可运行的 Railway Docker 部署配置：冻结依赖安装、构建 API/共享包、只部署 API 生产依赖、非 root Node 运行、通过 PORT 监听与 readiness 健康检查。密钥只能在运行平台变量中设置，不进入镜像/前端/Git；不自动执行 DDL。不提供未实际创建的 Railway 地址，也不声称已经部署。

本轮无数据库结构改变。Supabase 开关需项目管理者保存；Railway 发布需实际可用的平台配置。相册/等级/钱包仍在后续阶段。
